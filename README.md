# naite (나이테)

AI와 일하면서 실제로 틀렸던 자리들을 모았습니다. 사람이 읽는 목록이 아니라, **당신의 AI가 읽고 당신의 작업 환경을 고치는 데 쓰도록** 정리했습니다.

## 쓰는 법

작업 폴더의 파일을 직접 읽는 AI 에이전트(Claude Code나 Codex 같은 도구)에게 이 저장소를 건네고 이렇게 말하세요.

```
naite 저장소의 AI-START.md를 읽고 내 작업 환경을 진단해 줘.
개선안은 제안만 하고, 내가 승인하기 전에는 아무것도 바꾸지 마.
```

- **채팅 전용 AI는 진단 대상이 아닙니다.** 이 저장소는 AI가 당신의 지침 파일과 설정을 직접 읽는다는 전제로 짜여 있습니다. 채팅 AI에서 쓰는 방법은 아래에 따로 적었습니다.
- **저장소는 작업 폴더 바깥에 받아 두세요.** 이 저장소의 파일이 당신 작업의 지침으로 섞여 읽히지 않게 하기 위해서입니다.

AI는 당신 환경을 먼저 읽고, 없는 것만, 한 번에 다섯 개까지 제안합니다. 당신의 기존 규칙과 부딪히는 것은 바꾸지 않고 둘 다 보여 주며 묻습니다.

**이 저장소가 갱신되면 같은 한 줄을 다시 건네면 됩니다.** 적용한 문장 끝에는 `(naite SPEC-04 · v0.1.0)` 같은 표시가 붙습니다. AI는 이 표시와 [CHANGELOG.md](CHANGELOG.md)를 대조해 이미 넣은 것은 건너뛰고, 바뀐 것과 새로 생긴 것만 봅니다. 그러니 이 표시는 지우지 마세요. 폐기된 항목이 있으면 AI는 지우지 않고 물어봅니다.

## 채팅 AI에서 쓰려면

AI가 당신 환경을 진단하지는 못합니다. 대신 `starter.md`와 `tracks/spec/gates.md`의 "넣는 형태" 문장 중에서 필요한 것을 직접 골라 프로젝트 지침에 붙여 넣으세요.

- 고를 때는 각 항목의 **"안 통하는 상황"을 먼저 보세요. 당신 상황이 거기 해당하면 넣지 않습니다.**
- 스크립트나 설정이 필요한 부분은 채팅에서 쓸 수 없습니다. 문장만 가져가세요.

## 무엇이 있나

- **`AI-START.md`** — AI용 진입점. 사람이 읽을 필요는 없습니다.
- **`starter.md`** — 지침 파일이 아직 없는 사람을 위한 최소 묶음 다섯 개.
- **`tracks/spec/`** — 문서: 기획·정책·보고 문서를 AI가 읽을 수 있게 쓰고, 뒤떨어지지 않게 유지하는 자리.
  - `cases.md` — 사람용. 규칙 하나마다 그 규칙이 생긴 사건과 그래서 어떻게 하는지.
  - `gates.md` — AI용. 언제 이 규칙을 꺼내는지, 어떤 환경에서는 제안하지 않는지.
  - `kit/` — 복사해서 쓰는 템플릿과 프롬프트.
- **`tracks/setup/`** — 환경: 무엇을 물어보게 할지, 자격증명을 어디 둘지, 교정이 다음 세션에도 남는지, 같은 요청을 언제 도구로 굳힐지. 구성은 spec과 같습니다.
- **`adapters/`** — 도구마다 다른 파일 위치.

트랙은 추가만 됩니다. 이미 붙은 파일 경로와 항목 ID(`SPEC-01` 등)는 바뀌지 않으니, 당신의 지침 파일에 ID를 출처로 적어 두어도 됩니다.

## 이 방식이 통하는 조건

세 가지가 다 맞을수록 이 기록이 당신 것과 가깝습니다.

1. 내 결과물의 결정적인 부분이 텍스트로 적힌다.
2. 그 결과물을 받아서 다른 것을 만드는 사람이나 AI가 있다.
3. 같은 종류의 일을 반복한다.

## 한계

전부 한 사람의 기록입니다. 대조군이 없고 스스로 보고한 것이며, 같은 결과가 다른 곳에서도 나온다는 증거는 없습니다. **"이런 일이 최소 한 번은 실제로 일어났다"** 정도로 읽어 주세요.

규칙마다 "이 규칙이 안 통하는 상황"을 한 줄씩 붙였지만, 그 줄은 겪어서가 아니라 판단해서 쓴 것입니다. 당신 환경에서 반례가 보이면 당신 쪽이 맞습니다.
