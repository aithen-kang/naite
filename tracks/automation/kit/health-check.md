# kit · health-check — "살아 있나"가 아니라 "결과물이 늘어나나"

- **조건:** 스케줄러·트리거로 사람 없이 도는 작업이나 상주 프로세스를 운영한다
- **도구 의존:** 없음 — 점검 스크립트를 정해진 시각에 돌리는 방법은 운영체제 문서를 따른다
- **쓰는 ID:** AUTO-01 · AUTO-02 · AUTO-19 (AUTO-03의 알림 문구 포함)

## 1. 무엇으로 성공을 판정하나

| 작업 | 볼 산출물 | 실패로 보는 때 |
|---|---|---|
| 정해진 시각에 한 번 도는 작업 | 로그의 오늘자 성공 표식 | 마감시각까지 표식이 없다 |
| 상주 수집기 | 큐·저장 파일의 건수, 마지막 기록 시각 | 정해진 시간 동안 건수가 늘지 않는다 |
| 파일을 만드는 작업 | 출력 파일의 최신 시각과 **내용 크기** | 파일이 없거나, 있어도 내용이 기준에 못 미친다 |
| 발송 작업 | 게시 식별자 또는 실행 기록의 게시 성공 | "받았다" 응답만 있다 |

"파일이 있다"는 성공이 아니다. 추출·변환처럼 에러 없이 빈 결과를 내는 단계가 있으면, 건수·글자 수·면당 분량 같은 **내용 기준**을 하나 정해 둔다.

## 2. 오늘자 성공 표식

각 작업이 끝날 때 자기 로그에 한 줄을 남긴다.

```
2026-09-15 07:42:10 OK morning-report
```

마감시각 = 예정 시각 + 최대 소요 시간 + 여유. 그 시각에 아래 점검을 따로 돌린다. 점검이 본 작업과 같은 래퍼·같은 프로세스에 기대면 함께 죽으므로 떼어 둔다.

```python
# 오늘자 성공 표식 점검 — 마감시각에 한 번 돈다
import datetime
import pathlib
import sys

BASE = pathlib.Path(__file__).resolve().parent
JOBS = {  # 작업 이름: 로그 파일
    'morning-report': BASE / 'logs' / 'morning-report.log',
}

def notify(text):
    """당신 환경의 개인 수신 알림 함수로 바꾼다 (3절)."""
    print(text)

today = datetime.date.today().isoformat()
missing = []
for name, log in JOBS.items():
    lines = log.read_text(encoding='utf-8').splitlines() if log.exists() else []
    if not any(line.startswith(today) and f'OK {name}' in line for line in lines):
        missing.append(name)

if missing:
    notify(f'오늘자 성공 표식 없음: {", ".join(missing)}')
    sys.exit(3)
```

## 3. 알림 줄

- **개인에게 보낸다.** 채널은 다른 메시지에 묻힌다.
- **한 번 성공한 발송 경로를 지침에 적는다.** 자기 자신에게 보내는 주소는 도구마다 달라 추측이 잘 안 통한다. 주소 자체는 자격증명이라 환경 파일에 둔다.
- **예비 경로는 인증 방식이 다른 것으로.** 같은 인증에 기대는 두 경로는 함께 죽는다.
- **여러 사람이 보는 채널이면** 수치는 빼고 실패 사실과 복구 방법만 싣는다.
- **수집 대상에 보관 기한이 있으면** 발송 주기를 기한보다 짧게 잡고, 수집이 실패해도·수집물이 없어도 상태를 담아 보낸다.

실시간 수집 중단 알림 문구:

```
[수집 중단] {수집기 이름}
놓친 구간: {시작 시각} ~ {복구 시각}
이 구간에 보낸 중요한 것은 다시 보내 주세요.
```

## 4. 정체됐을 때 — 2단 복구

1. 산출물이 정해진 시간 동안 늘지 않으면 **재연결**을 시도한다.
2. 그래도 정체면 **종료 후 재기동**한다. 재기동 사이에 쿨다운을 둬서 재기동이 반복 폭주하지 않게 한다.
3. 연결 수·처리율 같은 **평시 정상 범위**를 기록해 둔다. 살아 있는데 아무것도 하지 않는 상태의 유일한 전조가 "평소와 다른 수치"였던 사례가 있다.

## 5. 알아 둘 것

- **첫 무인 실행은 지켜본다.** 손으로 돌려서 된 것과 스케줄러가 사람 없이 돌려서 되는 것은 다르다. 전원·절전 복귀·로그온 전후처럼 무인 환경에서만 나오는 실패가 있다.
- 스케줄러의 "실패 시 재시작" 같은 옵션이 무엇에 발동하는지는 운영체제마다 다르다. 스크립트가 실패 코드로 끝난 것에 발동하지 않았던 사례가 있다 — 재시도는 스크립트 안에 둔다.
