# kit · source-footer — 숫자가 손을 떠난 뒤에도 스스로 답하게

- **조건:** 숫자를 담은 파일(표·시트·리포트)이 대화와 떨어져 전달되고, 몇 주 뒤 "이 숫자 어디서 어떻게 뽑았나"라는 질문을 받는다
- **도구 의존:** 없음
- **쓰는 ID:** NUM-09 · NUM-14

리포트 파일은 대화와 분리되어 떠돈다. 파일이 스스로 답할 수 있어야 한다.

## 1. 모든 표·시트 하단에

```
─── 정보 ───
데이터: {시스템 이름} ({테이블·인덱스 식별자})
기간: {시작} ~ {끝} ({N}일 · {타임존} 기준)
생성: {YYYY-MM-DD HH:MM}
집계 조건: {정본 정의 요약 — 예: 기능을 한 번이라도 쓴 사용자}
참고: {다른 정의의 숫자 — 예: 접속 기준으로는 N명} · {근사/정확 차이의 원인}
```

## 2. 오독이 갈릴 숫자에는 표 안에 노트

같은 표에 해석이 갈릴 수 있는 숫자가 나란히 있으면, 받은 사람이 오독하지 않게 표 안에 한 줄을 둔다.

```
참고: 중복 제거 사용자 수와 일별 합산은 같은 사람을 여러 번 세느냐의 차이로 다르다 — 사람 수는 중복 제거 값이 정본이다.
```

## 3. 알아 둘 것

- **정본 정의는 footer보다 먼저 문서에 있어야 한다.** footer는 그 정의를 요약해 옮기는 자리다. 정의가 문서에 없으면 footer가 회차마다 다른 말을 한다.
- 근사 집계를 정본으로 쓰지 않을 때도, 둘이 왜 다른지(근사 오차·포함 범위의 차이)를 적어 두면 다음 사람이 다시 대조하지 않는다.
