# kit · credential-sweep — 인라인된 자격증명 찾기

- **조건:** 외부 서비스 자격증명을 쓰고, 설정·예제·문서·기록이 공유·백업·동기화된다
- **도구 의존:** 없음 (파일을 검색할 수 있는 AI 에이전트)
- **쓰는 ID:** SETUP-10

사용자 환경의 AI에게 그대로 건넨다. 찾기만 하고 고치지 않게 하며, **찾은 값을 화면에 출력하지 않게** 하는 것이 요점이다 — 점검하다 대화 기록에 값을 한 번 더 퍼뜨리면 안 된다.

```
이 작업 폴더에서 자격증명이 평문으로 들어간 곳을 찾아 줘. 고치지는 말고 보고만 해.

1. 찾을 곳: 권한·도구 설정 파일, 예제·템플릿 파일, 문서, 스크립트, 기록(로그·내보낸 대화).
   자격증명을 보관하기로 정한 파일(환경 파일)은 찾을 곳에서 뺀다.
2. 두 가지 방법으로 찾는다.
   - 이름: 키·비밀번호·인증 같은 이름이 붙은 항목
   - 값의 모양: 서비스 키의 고정 머리글자, 길고 무작위한 문자열, "계정:비밀번호" 형태,
     서명 값이 붙은 웹훅 주소
   이름으로만 찾으면 이름이 다른 곳에 들어간 값을 놓친다.
3. 찾은 값은 출력하지 않는다. 파일 · 줄 · 종류만 보고하고, 값은 앞 4자만 남기고 가린다.
4. 스크립트가 예외를 출력할 때 주소나 키 원문이 섞이는지도 본다.
5. 발견한 곳마다 조치를 제안한다.
   - 값을 환경 파일로 옮기고, 원래 자리는 환경 변수 참조로 바꾼다
   - 해당 키를 재발급한다 — 파일에서 지워도 과거 백업·기록에 남은 값은 되돌릴 수 없다
6. 파일을 고치거나 지우는 일은 내가 승인한 뒤에만 한다.
```

## 알아 둘 것

- **서명이 포함된 웹훅 주소는 자격증명이다.** 주소만 알면 누구나 인증 없이 요청을 보낼 수 있다.
- **"재발급까지가 조치 완료"는 판단에서 온 처방이다.** 원 기록에 있는 사건은 이름으로 찾다 값 하나를 놓친 데까지다.
- **예외 메시지 경로(4번)는 한 번 겪은 사례다** — 성공 경로에서는 마스킹이 됐는데, 실패 경로의 예외 메시지가 주소 원문을 출력했다. 1회라 규칙이 아니라 점검 항목으로 둔다.
