# kit · status-table — 반복 현황 질의를 "수집기 + 고정 표"로

- **조건:** 같은 현황·같은 형식의 요청이 두 번째로 왔고, 매 회차를 지난 회차와 비교해서 본다
- **도구 의존:** 수집 대상 시스템을 읽는 스크립트 하나
- **쓰는 ID:** SETUP-21

같은 현황을 매번 대화로 순회해서 답하면 회차마다 왕복이 크고 표 형태가 흔들린다. 두 번째 요청이 오는 순간 아래 네 요소로 굳힌다.

## 1. 네 요소

| 요소 | 규칙 |
|---|---|
| **수집 스크립트** | 수집 대상(티켓·하위 항목·코멘트)을 긁어 캐시에 저장한다. **판단하지 않는다** — 사실과 눈여겨볼 원문 조각까지만 출력한다 |
| **고정 컬럼 표** | 컬럼을 규약으로 고정한다. 갱신마다 형태가 흔들리면 이전 회차와 비교할 수 없다 |
| **비고만 AI가 쓴다** | 수집기가 뽑은 조각이 무슨 뜻인지만 비고 칸에 쓴다. 수집은 코드, 판단은 모델 |
| **상시 유지 비고 목록** | 매 갱신에서 살아남아야 할 예외 사실을 문서에 따로 적는다. 없으면 회차마다 AI가 그 예외를 다시 발견할지가 복불복이다 |

## 2. 문서 조각

```markdown
## {현황 이름} — 갱신 {YYYY-MM-DD}

> 수집: {스크립트 경로} · 컬럼은 고정이다. AI는 비고 칸만 쓴다.
> 분석·제안은 요청받았을 때만 붙인다.

| 대상 | 담당 | 단계별 상태 | 마지막 변경 | 비고 |
|---|---|---|---|---|
| {대상} | {담당} | {상태} | {YYYY-MM-DD} | {AI 서술} |

### 상시 유지 비고 — 매 갱신에서 살아남아야 할 사실
- {예: A 대상은 일정표에만 있고 담당 티켓이 없다}
- {예: 티켓 하나가 표의 두 행을 겸한다}
```

## 3. 운영 규율

- **요청자가 원하는 것은 표다.** 주기 갱신에 매번 분석이 딸려 오면, 정작 보고 싶은 "지난 회차와 무엇이 달라졌나"를 읽는 비용이 올라간다.
- **표의 행과 수집 대상 항목이 1:1이 아닌 경우가 반드시 생긴다**(항목 누락, 한 항목이 여러 행을 겸함). 스크립트에 행 ↔ 항목 매핑 표를 두고, 새 항목이 생기면 매핑부터 갱신한다.
- 이 수집기를 정해진 시각에 사람 없이 돌리기 시작하면, 그때부터는 무인 실행의 원칙(성공은 결과물로 판정, 실패 알림)도 함께 적용한다 — automation 트랙 AUTO-01 · AUTO-02.
