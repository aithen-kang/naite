# kit · coverage-checklist — 문답 커버리지 체크리스트와 중간 보고

- **조건:** 사용자와 문답하며 문서를 채운다. 반영 오류를 나중 리뷰에서 고칠 수 있다
- **도구 의존:** 없음
- **쓰는 ID:** SPEC-05

## 1. 시작 전 — 체크리스트를 먼저 합의한다

템플릿에서 거꾸로 뽑은 "문서에 들어가야 할 정보 목록"이다. 이 목록이 곧 "완료의 정의"가 된다. 순서대로 묻는 질문지로 쓰지 않고, 대화 흐름을 따르되 누락을 막는 기준으로 쓴다.

```
A. 공통 규칙
  □ 접근 권한
  □ 변경 저장 방식
  □ 오류 처리 패턴
  □ 교차 규칙 (외부 연동, 계정 정책 등)

B. 상태값
  □ 핵심 엔티티 분류
  □ 권한·역할 분류
  □ 주요 상태 전이

C. 단위별 정책 — 단위당 1세트
  □ 핵심 기능 (1문장)
  □ 주요 정책
  □ 진입·이탈 경로
  □ 예외 처리
  □ 권한별 분기 (같은 단위가 권한에 따라 다르게 보이는 경우)
  □ 입력 제약 (글자 수 제한, 필수·선택 등)
  □ 빈 상태 · 미감지 상태

D. 횡단 정책
  □ 두 단위 이상에 걸치는 정책 식별
  □ 정책 간 의존 관계

E. 시스템 메시지
  □ 발생 이벤트 목록

F. 미정
  □ 미정 항목
```

서비스 소개를 들은 직후, 이 목록을 그 도메인에 맞게 고친 초안을 보여 주고 **피드백을 한 번** 받는다. 빼거나 더할 항목과 단위 목록을 여기서 확정한 뒤 수집을 시작한다.

## 2. 문답 중 — 운용 4원칙

| 원칙 | 설명 |
|---|---|
| 흐름 우선 | 답에서 새 맥락이 나오면 파생 질문을 바로 한다. 체크리스트 순서에 얽매이지 않는다 |
| 누락 방지 | 한 영역이 어느 정도 채워지면 체크리스트에서 빈 항목만 골라 보충 질문한다 |
| 확인 최소화 | "맞나요?"를 반복하지 않는다. 바로 반영하고 리뷰에서 고친다 |
| 중간 보고 | 영역을 넘어갈 때 채운 것과 빈 것을 한 번 공유한다 |

## 3. 영역이 끝날 때 — 중간 보고 양식

```
현재 커버리지:
  A. 공통 규칙:  ✅ (4/4)
  B. 상태값:     ✅ (3/3)
  C. 단위별 정책:
    - {단위 1}:  ✅
    - {단위 2}:  🔄 ({빈 항목})
    - {단위 3}:  ❌ (미시작)
  D. 횡단 정책:  🔄 ({상태})
  E. 시스템 메시지: 🔄 ({채움}/{전체})

→ {다음 영역}으로 넘어갈까요?
```

사용자는 이 보고를 보고 순서를 정한다. 진행 상황이 보이므로 "언제 끝나나"를 따로 묻지 않아도 된다.
