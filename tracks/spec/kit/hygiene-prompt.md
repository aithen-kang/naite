# kit · hygiene-prompt — 문서 위생 검사기를 사용자 환경에서 만들게 하는 지시

- **조건:** 서로 참조하는 문서가 다섯 개를 넘는다. 사용자 환경에서 스크립트를 실행할 수 있다
- **도구 의존:** 실행 가능한 인터프리터 하나 (표준 라이브러리만 사용)
- **쓰는 ID:** SPEC-16

완성된 스크립트를 주지 않는다. 문서 구성·경로·표기 관행은 환경마다 달라서, 남의 환경에서 만든 검사기는 옮기는 즉시 오탐과 미탐을 낸다. 대신 아래 지시를 사용자 환경의 AI에게 그대로 건넨다.

```
이 작업 폴더의 문서 묶음에 맞는 문서 위생 검사 스크립트를 만들어 줘.

1. 만들기 전에 실제 문서를 스캔해 아래를 정하고 나에게 보고한다. 추측으로 채우지 않는다.
   - 검사할 폴더와 제외할 폴더
   - frontmatter를 쓰는 문서들의 공통 키 중 필수로 볼 것
   - 문서끼리 서로를 가리키는 표기 변형 — 코퍼스에서 실제로 수집한 목록으로 보고한다.
     변형 하나를 놓치면 그 계열 전체가 검사 밖으로 빠진다.

2. 검사 항목
   H1 링크 대상 존재 — 마크다운 링크의 대상 파일이 실재하는가.
      외부 URL과 코드 펜스 안의 예시는 제외한다.
   H2 절 참조 대상 존재 — 다른 문서의 절을 번호로 가리키는 표기에서, 그 문서에 그 번호의 제목이 있는가.
   H3 frontmatter — 필수 키가 있고, 날짜 칸이 날짜만 담고 있는가.

3. 하지 않는다
   - 내용 계약 검사(표의 완결성, 미결 건수 대조) — 구조가 바뀔 때마다 다시 써야 한다
   - 자동 수정 — 잘못된 대상으로 조용히 연결하게 된다. 보고만 한다
   - 외부 라이브러리 설치
   - 문서 쓰기·삭제·이동 — 읽기 전용이다

4. 출력
   - 위반마다 한 줄: 항목 코드 · 파일:줄 · 무엇이 틀렸고 어떻게 고치나
   - 통과하면 한 줄로 끝낸다
   - 종료 코드: 0 통과 / 1 위반 / 2 실행 오류
   - 이 폴더의 콘솔에서 한글 등 출력 문자가 깨지지 않게 한다

5. 만든 직후 임시 사본에서 일부러 깨뜨려 본다
   ① 링크 대상 파일명 한 글자 변경 ② 절 번호를 없는 번호로 변경 ③ frontmatter 키 하나 삭제
   셋 다 해당 항목 코드로 잡히는지, 원본에서는 통과 + 종료 코드 0인지 보고한다.
   종료 코드만 보지 말고 기대한 메시지가 나왔는지도 본다 — 크래시도 같은 코드로 끝날 수 있다.

6. 마지막으로, 문서 구조를 바꾼 작업 끝에 이 검사를 돌린다는 한 줄을 내 지침 파일에 넣을지 묻는다.
```

## 알아 둘 한계 — 사람에게도 전한다

- **검사기는 절 번호가 어느 문서를 가리키는지 스스로 알 수 없다.** 문서 이름을 생략한 참조는 자기 문서의 절로 읽히고, 우연히 같은 번호가 있으면 **틀린 채 통과한다.** 그래서 검사기의 판정은 쓰는 쪽의 표기 규율에 기댄다 — 다른 문서의 절에는 문서 이름을 항상 붙이고, 범위·복수 표기는 한 덩어리로 쓴다.
- **반대로, 참조처럼 생겼지만 검사 대상이 아닌 번호는 위반으로 잡힌다** — 폐기된 절을 인용한 변경 기록, 표기법을 가르치는 예시, 외부 문헌의 절 번호. 변경 기록 섹션을 H2에서 빼거나, 예시에는 절 기호를 쓰지 않는 식으로 환경에 맞게 정한다.
- **검사기는 표기만 잡는다.** 한 문서의 규칙이 다른 문서의 규칙과 모순되는 것, "구조를 확정한다"고 적힌 규약 문서가 실물과 달라진 것은 어떤 문자열 검사로도 안 잡힌다. 새 규칙을 만들 때 어긋날 수 있는 기존 문서를 찾아 같이 고친다.
- 주의(1회 사례, 규칙 아님): 백틱을 예시가 아니라 실제 참조의 강조로 쓰는 환경에서는, 코드 스팬을 절 참조 검사에서 빼면 가장 중요한 표가 통째로 검사 밖이 된다. 링크 검사와 절 참조 검사의 제외 규칙을 따로 정한다.
