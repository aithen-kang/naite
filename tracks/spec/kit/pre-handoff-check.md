# kit · pre-handoff-check — 문서를 넘기기 전 · 바꾼 작업을 보고하기 전

- **조건:** 문서를 다른 사람이나 다른 AI(다음 세션의 AI 포함)에게 넘기고, 받는 쪽이 문장을 그대로 실행 대상으로 읽는다(앞의 세 칸). 또는 값 · 선택 · 구조를 바꾼 작업을 완료 보고한다(넷째 칸)
- **도구 의존:** 없음
- **쓰는 ID:** SPEC-17

```
□ 작업 지시문이 남아 있지 않은가
  — "다음 세션에서 ~를 작성한다", "2단계에서 채운다" 같은 작성 과정의 문장.
    받는 AI는 이것을 정책이나 할 일로 읽는다.

□ 본문에서 확정한 항목이 미정 목록에 그대로 남아 있지 않은가
  — 사람은 맥락으로 걸러 읽지만, AI는 미정 목록을 믿는다.
    미정 표시 개수와 미정 목록의 항목 수가 맞는지 센다.

□ 폐기하기로 한 값이 표시 없이 살아 있지 않은가
  — 프로토타입 단계의 임의 값(글자 수 제한, 해상도 등).
    표시 없이 본문 어딘가에 남으면 그대로 구현된다.
    폐기값 목록을 문서 머리나 진입 문서에 따로 적어 두면 이중으로 막힌다.

□ 값·선택·구조를 바꿨다면, 옛 값을 검색한 결과를 보고에 붙였는가
  — 검색 범위: 이번에 건드린 문서 + 그 문서를 참조하는 문서.
    보고에 적을 것: 검색어 · 결과 건수 · 남긴 것이 있으면 그 이유.
    "고쳤다"만 있는 보고에서는 빠진 곳이 보이지 않는다.
    새 파일만 만들었거나 한 곳만 고쳤다면 건너뛴다.
```

문서에는 결과만 남긴다. 과정은 세션 기록이나 인수인계 메모에 둔다.
