# kit · publish-guard — 게시본을 덮어쓰지 않게

- **조건:** 로컬 문서를 위키·게시판·CMS에 올리고, 올린 뒤 사람이 게시본을 손보거나 댓글이 붙는다
- **도구 의존:** 게시 스크립트가 있을 때만 코드 조각이 필요하다. 없으면 규약만 쓴다
- **쓰는 ID:** SPEC-18

## 1. 규약

| 규약 | 내용 |
|---|---|
| 정본 | 로컬 문서. 내용과 문구의 단일 출처 |
| 게시 반영 | 수동·부분 적용. 문서가 바뀌면 "이 부분 반영 필요"를 사람에게 알리고, 사람이 해당 부분만 반영한다 |
| 자동 전체 재게시 | 금지. 게시본의 사람 손질을 보존할 수 없다 |
| 부득이 스크립트로 게시할 때 | ① 제목이 아니라 페이지 ID 기준으로 갱신한다(제목이 바뀌어도 중복 페이지가 안 생긴다) ② 한 번에 한 페이지 ③ 사람이 확인한 뒤에만 |
| AI가 만든 게시물 | 상단에 검증 상태를 적는다 — "담당자 검증됨" / "AI 초안 — 검증 전" (SPEC-19) |

## 2. 가드 — 스크립트 자체에 심는다

방침으로만 두면 언젠가 AI 세션이, 혹은 미래의 내가 잊고 실행한다. 덮어쓰기·삭제·대량 발송 모드의 진입부에 넣는다.

```python
import os, sys

# 게시(덮어쓰기) 모드 진입부
if os.environ.get('PUBLISH_OK') != '1':
    sys.exit("게시 거부: 자동 재게시 금지 방침. 정말 게시하려면 "
             "PUBLISH_OK=1 환경변수를 명시하고 다시 실행하세요.")
```

이러면 게시는 항상 의도적인 행위가 된다. AI에게 "게시해 줘"라고 시켜도 가드에서 멈추고, 사람이 변수를 명시해야만 진행된다. 다른 언어로 쓰는 스크립트도 같은 모양 — 명시적 허가 변수가 없으면 원인과 다음 행동을 알려 주고 종료 — 으로 옮긴다.
